# AGENTS.md

kiln is a Bun + TypeScript terminal UI (OpenTUI React) that opens native Claude, Codex, OpenCode, Pi, Muse and Antigravity TUIs, plus read-only cloud discovery, a localhost phone API and an Android client. Arch users install it from the AUR as `kiln-agents`, which a `v*` tag publishes.

## Commands

- `bun install --frozen-lockfile`, then `bun run gate` (biome, tsc, tests, changelog check) or `bun run gate:changed` (biome on changed files, tsc, the tests named for those files, changelog check). CI runs the same plus actionlint, zizmor, gitleaks, native x64 and arm64 binary jobs and the Arch package install.
- `bun start` opens the TUI; it needs `fzf` and `tmux` on `PATH`. Perf and TUI end-to-end: `bun scripts/perf.ts`, `bun scripts/list-tui-e2e.ts`, `bun scripts/native-tui-e2e.ts`.
- Phone changes also run `ANDROID_HOME=/path/to/sdk android/gradlew -p android checkKotlinFormat testDebugUnitTest lintDebug assembleDebug`.
- After every visible change, regenerate and inspect the terminal and mobile mock screenshots: `bun scripts/screenshots.tsx 2>/dev/null`, and `ANDROID_HOME=... JAVA_HOME=<jdk21> python3 scripts/android-screenshots.py` (a dedicated emulator, never a real phone). `python3 scripts/icons.py` and `scripts/wordmark.py` regenerate the mark and wordmark from `assets/icon.svg`.

## Invariants

- Activity is a closed set (`working`, `waiting`, `idle`). Map each agent's own states onto it with an exhaustive switch, never a fallthrough guess. Unknown stays unknown; pane output is not working status.
- Anything that can fail at startup (a bad settings file) is reported before the TUI takes the screen; nothing prints to the console while it is up. Unknown keys in `~/.config/kiln/config.toml` are errors.
- `src/sessions.ts` `discovery()` merges native and cached cloud rows and drops `elsewhere` ones kiln cannot open; each source keeps its last rows while it fails. `sessionIdentity` is the one name for a session in the list, on the phone and in notifications.
- `kiln status` (`src/status-cache.ts`) prints one cached line shared by every client; only the caller holding the lock refreshes it.
- A session's status comes from its own agent: Claude transcripts and background-job `lifecycle`, Codex daemon, Pi's per-process status file (`pi-extension/kiln-status.js`, loaded by `pi -e`), OpenCode's loopback service. Kiln passes OpenCode its `--session` id; a terminal with no id in argv is never paired by directory. Muse (`src/muse.ts`) publishes no status: its sessions are found by process, named by the live-session registry or the session log a process holds open, and stay unknown except a `muse exec` run, which is working while its process runs. Antigravity (`agy`, `src/agy.ts`) is found by process and named by the `conversations/<id>.db` the process holds open (none before its first prompt, so such a row has no id); status is the `status` of its row in `conversation_summaries.db` (plus `waiting_steps` in `raw_summary`, including nested in-process subagents, for `waiting`), opened read-only; a `-p` run is working while its process runs. agy cannot be given a conversation id, so `kiln msg spawn agy` finds the id after start like Codex.
- Accounts (`src/accounts.ts`, `[[accounts]]`): each is a config home pinned by the agent's own variable; Claude's default is `~/.claude` with `CLAUDE_CONFIG_DIR` unset (`routed` in `src/routing.ts`). A Claude home owns only `.credentials.json` and `.claude.json` and links the rest to `~/.claude`. Claude usage is the provider's `oauth/usage` answer for the login's token (`src/claude-usage.ts`); kiln never refreshes or writes a token. A Claude run's limit is the `rate_limit` record in its own transcript (`src/limits.ts`). An expired Claude token is Claude Code's to renew: kiln runs `claude auth status` in the home, at most every half hour; a login that cannot be renewed is `needsLogin` and never routed to. `disabled` accounts and `[[pins]]` (`accountDisabled`, `pinFor`) are applied in `routeNew`; a pinned run is refused, never moved. `src/account-failover.ts` (`failOverLimited`), called by the list and the phone server, restarts an interactive Claude session whose transcript shows a limit in its own pane on another account, claimed once across processes by a state file; a headless spawn is left to its exit report (`interactive` on the spawn record tells them apart).
- Saved sessions (`src/saved-sessions.ts`) from an earlier boot list as `stopped`; resuming keeps the pane (`remain-on-exit`) until discovery lists the conversation, and puts the stopped row back on failure.
- `kiln msg` delivers by agent: OpenCode service, Pi extension inbox, Codex `turn/start`, Claude's peer inbox socket confirmed by the transcript's `queue-operation` record, Muse's `session-message send`, else tmux paste (the only route into agy, and only for panes kiln started). Typing waits for `idle` or `turnEnded`. A sender in a sandbox that hides the sessions never discovers: a spawned child writes to its outbox (`KILN_OUTBOX`, granted to Claude's sandbox by `allowWrite` and to Codex's by `--add-dir`), which its spawn's exit watcher relays as from that child. A Codex worker that must run git spawns with `--dir` at a linked worktree, or at the main checkout to work in any of its linked worktrees: kiln grants each such worktree's checkout and admin dir plus the common `objects`, `refs` and `logs`, never the common dir or its `worktrees/` dir. Git in the main checkout itself stays read-only, since its `index` and `FETCH_HEAD` are root files of the common dir. The bundled skill is `skills/kiln/`. Kiln cannot read a Muse transcript (`muse export` is trajectory records), so `kiln msg view` shows nothing for Muse and a Muse child answers by message. agy transcripts are undocumented protobuf `steps` rows, so the same holds for agy.
- Phone: starting sessions and sending prompts is gated by `[phone] write` (off by default). A start may name an `account`, routed as `--account` is. The `moved` and `available` pushes come from the server comparing its own reads, not from the failover claim, so they are sent whichever watcher acted. Keep credentials out of URLs and logs; handoffs accept only verified provider HTTPS links or a one-use `/opencode/<code>` path.
- Closing a Codex pane archives its thread, except a headless `kiln msg spawn` child: `codex exec resume <id>` refuses an archived thread, and coordinators resume children by id to hand back review findings.
- `src/tmux.ts` and `tmux.conf` drive kiln's private tmux server (`tmux -L kiln`), no prefix, one detach key.
- `src/bundled-skills.ts`, `skills/`: helpers synced to the shared user store before the TUI starts. Preserve unowned same-name skills and back up edits to managed instructions before upgrades.

## Releases

- Every version needs a `CHANGELOG.md` entry (prose, bold-lead bullets) before its tag. README and changelog copy is plain and concrete: no marketing words, no em dashes.
- Prepare release metadata on a PR branch; the release helper updates desktop and Android together. Its separate tag action requires the merged origin/main commit. Never push main directly.
- Android releases use repository signing secrets and attach a signed APK; private signing material stays outside the repository.
- Bugpatrol runs `scripts/qa-drive.ts` and `scripts/qa-phone.ts` (seeded; never the real sessions or a paired phone). Live roots and settled shapes for cleanup work are in `.sloppatrol/instructions.md`.
